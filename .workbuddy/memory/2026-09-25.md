## AI 功能评审与优化建议（docs/08-AI功能优化建议.md）

- 通读 AI 全链路（`core/ai/*`、`core/insight/*`、`features/ai/application/*`）+ 06/07/ADR-0006，产出优化建议文档。
- **P0 四项（会产生错误输出，均为既有代码小改、无新依赖）**：
  1. `weekly_report.dart:91` 环比拿「本周部分周」比「上周完整周」→ 周一显示接近 -100%，且被 prompt 要求原样引用，AI 会把它当结论说出口。建议改对齐进度口径（上周截取到同一星期几同一时刻）。
  2. `ai_controller.dart` 解读缓存只按周键 `{week, text}` → 周一生成的解读整周不复更新，周日看到的还是周一快照。建议缓存加 fingerprint（sessionCount/minutes/interruptionCount），变化超阈值仅给**一行被动提示**，不自动重发（守安静原则）。
  3. 解析器过脆：`parseInsightResponse` 只用 `\n\s*\n` 切段 + `startsWith('建议：')` 精确匹配；问答/点评只取首个非空行 → 模型用单换行分段或输出 `**建议：**` 即**整体降级**。建议段落回退单换行、正则识别建议段、清 Markdown、跳客套开场白。
  4. `deepseek_provider.dart:99` `maxInsightTokens=600` 三处共用，而点评契约只有 40 字、问答 80 字 → 非流式请求等于按 600 token 的生成时间白等（约 30s）。建议 `generateInsight(prompt, {maxTokens})` 分档：周报 600 / 问答 200 / 点评 120。**单项投入产出比最高。**
- **P1**：temperature 0.7→0.3 且拆 system message；数据量门槛（本周 0 分钟不该发请求，顺带省钱）；`buildPrompt`/`buildAskPrompt` 与 `buildDailyPrompt`/`buildDailyAskPrompt` 两组事实块逐行重复应抽共用；`InsightEngine` 没吃满已有数据（**中断的时段分布**——pauses 已带时间戳却只累加计数，导致「怎样减少中断」这题无数据可答；另有中断占比、周维度最长段、4 周滚动基线）。
- **P2**：**「AI 建议兑现追踪」**（缓存改按周列表 + 展示上周 AI 建议 + 本地规则判定是否见效）——零新增 LLM 调用、零新增上传字段，补上「复盘→改进」闭环最后一环，最推荐；自定义 OpenAI 兼容端点（解锁本地 Ollama）；`mikufocus_ai_config.json` 导入解决 M500 手打 Key 的摩擦。
- **不做**：流式（先做 P0-4 压延迟，若周报仍 >15s 再评估）、端侧 LLM、语音、主动推送、AI 聊天输入框。
