# ADR-0006：AI 功能立项——AI 周报解读（云端 LLM + 本地 InsightEngine）

**Status**: Accepted (2026-08-27)

关联：[ADR-0005](./0005-simplicity-experience-first.md)（本 ADR 部分取代其中「AI 建议砍掉」条款）、[AI 功能调研报告](../05-AI功能调研报告.md)、[AI 功能 PRD](../06-AI功能PRD.md)、[AI 功能技术方案](../07-AI功能技术方案.md)、[PRD](../02-PRD-产品需求文档.md)、[词汇表](../../CONTEXT.md)

## Context

ADR-0005 在评审第三方规划报告时**明确砍掉了「AI 专注建议」**，理由是功能堆叠——在熄屏盲操作场景下，每多一个功能，无屏操作成本指数上升。该决策本身正确，但其针对的对象是第三方报告设想的**打扰式/堆叠式 AI**（AI 主动给建议、AI 作为新交互入口），而非一切 AI 形态。

2026-08-27，项目所有者在完成 AI 功能专项调研（[05-AI功能调研报告](../05-AI功能调研报告.md)）后决定立项 AI 功能。调研给出的关键事实：

1. **竞品 AI 渗透很浅**：专注类 App 的 AI 基本是「统计数据的 AI 化包装」（番茄ToDo 的 AI 专注质量评估），Forest/潮汐无大模型功能——既无壁垒也无大坑；
2. **用户态度分化明确**：反感「AI 打扰/喧宾夺主」（微软 Copilot 广告被抵制；「AI-maxxing」61% 员工担忧），接受「AI 安静省时、结果一眼可验证」——被反感的是打扰型 AI，不是安静型 AI；
3. **端侧 LLM 不可行**：骁龙 680（4GB RAM、无 GMS、A73+A53 老架构）上，Gemini Nano 需 12GB RAM+旗舰芯片且仅限 Pixel/三星等；MediaPipe LLM 低端 GPU 初始化失败；llama.cpp 1B 模型在更强的骁龙 6 Gen 3 上仅 12-18 tok/s、3B 仅 4-7 tok/s 且占 2.2GB 内存——**端侧 LLM 对话不做**；
4. **端侧 ASR/TTS 可行**：sherpa-onnx 提供 Android AAR，Zipformer-small 中文模型 14MB 可实时识别，全离线；M500 定制 ROM 大概率无 GMS，系统语音能力按不可用设计；
5. **云端成本可忽略**：本项目场景（每周一次、几百字进出）单用户年成本分—角级（DeepSeek 输入约 $0.20/百万 token 量级且新用户赠 500 万 token）；
6. **隐私合规路径清晰**：个保法最小必要原则下，只上传匿名聚合统计（匿名化聚合数据不属于个人信息），剥离设备标识，单独同意，默认离线可用；
7. **混合架构有先例**：三星 Driving Insights、飞书 AI 周报验证了「本地规则引擎产出结构化洞察 + LLM 只做自然语言润色」的成立性。

需要解决的张力：如何在不破坏 ADR-0005「简洁为主、体验第一」铁律的前提下引入 AI。

## Decision

1. **立项 AI 功能，定位为「已有专注数据的增值解读层」，不是新交互入口**。唯一功能：**AI 周报解读（V0.5）**——本地规则引擎（InsightEngine，复用 weekly_report / focus_heatmap / focus_interruption 数据）产出结构化洞察 → 用户在统计页主动点击「AI 解读」→ 云端 LLM（首选 DeepSeek，LlmProvider 抽象可换 Kimi/通义）生成自然语言复盘 + 一条可执行建议；无网/未配置 Key 时退化为现有纯结构化周报。
   **砍除记录**：TTS 语音播报与语音速记曾列入三件套（V0.5 端侧播报 / V0.6 FN 键语音速记），经所有者决策于 2026-08-27 全部砍掉——理由：专注单一云端路线、降低硬件联调风险（TTS 与 M500 定制 ROM 音频焦点的 duck 共存、sherpa-onnx 端侧模型资源占用均未真机验证）。端侧 ASR/TTS 调研结论在 [05-AI功能调研报告](../05-AI功能调研报告.md) §3.2 留档备查。
2. **本 ADR 部分取代 ADR-0005 中「AI 建议砍掉」条款**。取代范围仅限：**用户主动触发、只解读已有数据、默认可关的安静型 AI**；ADR-0005 的其余全部内容（两种计时模式、极简按键映射、声震反馈 <100ms、砍掉成就/社交/穿戴/无关采集、拦截移出路线图）**不受影响、继续有效**。取代理由：所有者决策 + 调研证明被用户反感的是打扰型 AI、安静省时型 AI 被接受，且混合架构保证离线核心功能不受 AI 可用性影响。
3. **AI 安静原则作为红线约束全部 AI 功能**（与 ADR-0005 的关系是延伸而非放松）：
   > AI 永不在计时进行中发声/弹窗/主动推送建议；AI 输出只在用户主动查看处呈现；设置页提供一键全局关闭 AI 的开关；AI 功能全部默认关闭，需用户主动开启并单独同意数据使用说明。
4. **技术路线**：云端 LLM（HTTPS）+ 本地 InsightEngine（纯 Dart），无原生依赖；**端侧 LLM 对话在骁龙 680 上不可行，明确不做**（调研依据见 Context §3）；端侧 1B 级小模型做打标/分类仅列为远期实验项，不承诺进路线图；端侧 ASR/TTS 随语音功能一并砍掉。
5. **隐私最小化**：只上传匿名聚合统计（时长/次数/时段分布/弹性连续天数/中断来源的匿名类别），剥离设备标识，不上传原始事件流和应用名明细，单独同意，默认离线可用（字段级清单见 [07-技术方案 §5](../07-AI功能技术方案.md)）。
6. **边界条件（防范围蔓延）**：任何 AI 需求若涉及下列任一项，须另立 ADR 评审——AI 主动推送/计时中介入；LLM 参与计时或统计决策；上传白名单之外的字段；端侧 LLM 对话；重启任何语音类功能（TTS/ASR/速记）；Motion 式排程自动化；多模态。

## Consequences

**正面**：
- 补齐市场调研痛点 Top7「统计浅、缺复盘」的最后一环：V0.4 的结构化数据之上有了人话解读，形成「专注-数据-复盘-改进」完整闭环；
- 混合架构下 LLM 只做润色，**断网/欠费/超时/解析失败均零功能损失**，离线优先的产品承诺不破；
- 默认关闭 + 单独同意 + 一键全关，AI 对不需要它的用户**零存在感**，ADR-0005 的简洁体验不受影响；
- 砍掉语音功能后 AI 模块无任何原生依赖与硬件联调面，V0.5 交付风险显著下降。

**负面与缓解**：
- 引入首个网络依赖与第三方服务（云端 LLM）：以 LlmProvider 抽象 + 全路径降级矩阵（[07 §6](../07-AI功能技术方案.md)）隔离，核心链路零依赖；
- 语音类差异化卖点（免触屏播报、语音速记）随之放弃：调研结论已留档（[05](../05-AI功能调研报告.md) §3.2），未来若重启须另立 ADR（Decision §6 边界条件）；
- 「部分取代」带来 ADR 间的引用复杂度：已在 ADR-0005 加备注行回指本 ADR，两份文档必须一起读；
- 远期端侧 1B 打标可能诱发「再试端侧 LLM」的范围蔓延：以 Decision §6 的边界条件清单为闸口，任何越界需求另立 ADR。
