# ADR-0005：简洁与体验第一——极简按键映射、声震即时反馈、两种计时模式

**Status**: Accepted (2026-07-19)

> 注（2026-08-27）：本 ADR 中「AI 建议砍掉」条款已被 [ADR-0006](./0006-ai-features-scope.md) 部分取代——AI 以「数据增值解读层」形态立项，仍受简洁与安静原则约束。

关联：[PRD](../02-PRD-产品需求文档.md)、[技术架构设计](../03-技术架构设计.md)、[04-批判评审与方案优化](../04-批判评审与方案优化.md)、[ADR-0001](./0001-audio-service-media-session-hijack.md)、[词汇表](../../CONTEXT.md)

## Context

第三方规划报告（`docs/reference/ai-clock-product-plan/ai-clock-product-plan.html` v1.1，仅素材留档）提出了与本产品形态不符的方案：

1. **功能堆叠**：6 种计时模式（番茄/50-10/正计时/Flowtime/自定义间隔/冲刺）、每枚按键短按/长按/双击全占用、成就等级商店、AI 建议、社交自习室、穿戴联动、心率/天气/位置采集；
2. **技术路线错误**：以「按键直连 GPIO」为由弃用 audio_service 改写裸 MediaSession + flutter_foreground_task，并用 `repeat(1000)` 每秒唤醒做计时；Drift + Hive 双库存储。

本产品的核心场景是**熄屏、不碰屏幕的盲操作**。该场景下体验完全取决于两点：**反馈**（按下去有没有被收到）与**可记忆性**（哪个键干什么）。功能每多一个，无屏操作的成本不是线性而是指数上升——用户无法看一眼屏幕来回忆交互。两项设计依据：

- **Fogg 行为模型 B = MAP**：行为 = 动机 + 能力 + 提示，三者缺一不可。对应：按键免触屏（降能力门槛）、声震即时反馈（明确提示）、轻量正向反馈（维持动机）；
- **Gloria Mark（UC Irvine）中断成本研究**：被打断后约 23 分钟才能回到原任务——「少打断」是效率目标，规则必须简单可预期（引自第三方规划报告 v1.1 的素材部分）。

## Decision

以「极简按键映射 + 声震即时反馈 + 两种计时模式」为产品边界：

1. **计时模式仅两种**：番茄倒计时（默认 25/5，4 轮后长休；50/10 仅作为时长预设）+ 正计时（不限时，支持打点标记）。拒绝 6 模式堆叠。
2. **极简按键映射**（默认，10 秒能学会）：

   | 按键 | 手势 | 语义 |
   | --- | --- | --- |
   | 播放/暂停 (85) | 单按 | 开始 / 暂停（唯一必须记住的按键） |
   | 播放/暂停 (85) | 长按 | 结束本次专注并保存记录（长按自带确认感，防误触） |
   | 下一曲 (87) | 单按 | 跳过当前阶段（专注→休息；休息→直接开始下一段专注） |
   | 上一曲 (88) | 单按 | 当前专注 +5 分钟（正计时模式下 = 打时间标记点） |

   双击/三击：ClickGrouper（800ms 窗口）代码保留、默认映射为空，V0.2 随按键自定义开放；FN 键 V0.2 预留为「一键开始上次模式」。
3. **每次按键必须有声音/震动的即时确认反馈**（端到端延迟 <100ms，可分别开关）——免触屏场景下没有反馈等于盲操作，这是体验的第一优先级，列为 V0.1 核心需求。
4. **维持既有技术决策，拒绝 HTML 技术路线**：audio_service 霸占 MediaSession（ADR-0001，直连只解决事件来源不解决路由）；时间戳差值计时（拒绝每秒轮询）；drift + shared_preferences（ADR-0002，拒绝双库）。
5. **明确砍掉**：多计时模式堆叠、成就系统/等级商店、AI 建议、社交自习室、穿戴联动、心率/天气/位置采集；应用拦截/学霸模式移出路线图。

## Consequences

**正面**：
- 10 秒能学会、盲操作可信：需要记忆的按键只有一个，其余三个语义符合音乐播放肌肉记忆；
- 声震反馈让「按键是否生效」无需看屏即可确认，直接消除盲操作的最大不确定性；
- 范围收敛后 V0.1 MVP 可交付性显著提高；ClickGrouper、Command 映射层、feature 插件目录等扩展点全部保留，未来加功能不动核心。

**负面与缓解**：
- 双击/三击手势短期闲置：解析能力保留，V0.2 按键自定义开放后由用户自行启用；
- 「空闲时按键直接开始」受会话霸占策略限制（空闲时按键归音乐 App，事件到不了本 App——这是主方案文档此前未指明的一处矛盾）：首次开始走触屏大按钮/通知按钮，V0.2 由 FN 键（独立原生按键通道）承担一键开始；
- 功能少于同类 App 可能在对比评测中被诟病：以「10 秒学会、全程不碰屏」的体验口碑对冲，版本路线图保留全部扩展点。
