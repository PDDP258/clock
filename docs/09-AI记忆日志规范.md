# 09 · AI 记忆日志规范（跨程序记忆）

> 状态：V0.5 已落地（2026-09-26，看板 #54）
> 代码：`lib/core/ai/memory_log.dart`（格式）/ `lib/platform/files/memory_log_store.dart`（读写）
> 单测：`test/memory_log_test.dart`（本文档的可执行版本）
> 相关：[07-AI功能技术方案](./07-AI功能技术方案.md) · [08-AI功能优化建议](./08-AI功能优化建议.md) · ADR-0006

## 1. 一句话

**改这个文件，就是给本机 AI 传记忆。**

本机 AI 每天把「看到的数字」和「说过的话」写成一个文本文件（一天一条）。
近 7 日会被自动注入到每一次请求里；外部程序只要按本文档读写这一个文件，
就能与本机 AI 交换记忆——不需要接入本项目的任何接口、任何网络协议、
任何 SDK。这是刻意的选择：**最稳的互操作格式是纯文本 + 一行一个 JSON**。

---

## 2. 文件位置

| 项 | 值 |
| --- | --- |
| 文件名 | `mikufocus_ai_memory.jsonl` |
| 目录 | 应用专属外存 `/sdcard/Android/data/com.aiclock.player/files`（取不到时回退应用文档目录） |
| 同目录邻居 | `mikufocus_backup.json`（专注记录备份）——同一套「文件管理器自取自放」通路 |
| 设备内查看路径 | 设置 → AI 功能 → **跨程序记忆日志**（可直接复制完整路径） |

目录免存储权限（Android 10+），用户与外部程序用文件管理器 / MTP / adb 均可读写。

---

## 3. 文件格式总则

- **UTF-8**（读取容忍首字节 BOM）；
- **一行一个 JSON 对象**，行尾 `LF`（读取容忍 `CRLF`）；
- 行序按 `date` 升序；**同一 `date` 只允许一条**（同日重复时**后出现者胜出**）；
- 无法解析的行**不会被删除**：应用写回时把它们原样附在文件末尾；
- 读取时**不做隐式修复**，只做容错解析（见 §6）。

> 为什么不是一个大 JSON 数组？因为**追加与局部修改的成本**。
> 一行一条时，外部程序改一天的数据只需重写一行；数组结构必须整体重写，
> 一旦写入中断就是全文件报废。原子写 + 一行一条是这里唯一合理的组合。

---

## 4. 单条结构

```json
{"schema":"aiclock.ai_memory/1","date":"2026-09-26","rev":3,"updated_at":"2026-09-26T21:12:05+08:00","prompt_version":"v3","facts":{"focus_minutes":95,"sessions":3,"rounds":4,"longest_segment_minutes":50,"interruption_count":2,"interruption_minutes":5,"best_slot":"下午"},"note":"今天 95 分钟里有 50 分钟是连着的一段。","insight":"…","memory":"最近在赶论文，夜里效率反而高。","source":"pc-script"}
```

### 4.1 字段表

| 键 | 类型 | 归属 | 必需 | 说明 |
| --- | --- | --- | --- | --- |
| `date` | string | 应用 | **是** | `yyyy-MM-dd` 本地日期，**文件内唯一键** |
| `schema` | string | 应用 | 建议 | 固定 `aiclock.ai_memory/1`；外部程序据此判断格式 |
| `rev` | int | 应用 | 建议 | 该条目被写入的次数，同日每次重写 +1；缺失按 1 |
| `updated_at` | string | 应用 | 建议 | 最近写入时刻，ISO-8601 带时区偏移；缺失按空串 |
| `prompt_version` | string | 应用 | 否 | 写入时的提示词版本，用于判断旧条目的文风世代 |
| `facts` | object | 应用 | 否 | 当日白名单数字快照（键见 §4.2） |
| `note` | string | 应用 | 否 | 当日 AI 一句话点评 |
| `insight` | string | 应用 | 否 | 当日新生成的周报解读（压平为单行） |
| `memory` | string | **外部** | 否 | **外部程序传记忆的约定键**，优先级见 §5.3 |
| 其它任意键 | 任意 | **外部** | 否 | 应用原样保留，永不改写（可用于 `source` / `tags` 等自定义元数据） |

### 4.2 `facts` 允许的键（白名单）

与 [07 §4.1](./07-AI功能技术方案.md) 的发送白名单同源，**只有时长/轮数/时段聚合**：

| 键 | 例 | 说明 |
| --- | --- | --- |
| `focus_minutes` | 95 | 当日实际专注分钟 |
| `sessions` | 3 | 当日会话段数 |
| `rounds` | 4 | 当日完成番茄轮数 |
| `longest_segment_minutes` | 50 | 当日最长单段专注 |
| `interruption_count` | 2 | 当日专注内暂停次数 |
| `interruption_minutes` | 5 | 当日暂停总分钟 |
| `best_slot` | `"下午"` | 当日最佳时段（`凌晨`/`上午`/`下午`/`晚上`） |

**没有**：钟点（`09:12`）、应用名、标签、任何内容维度。
应用自己写 `facts` 时只写这张表；外部多写的键不会影响解析，但**会被注入发送**（见 §7）。

## 5. 写入规则

### 5.1 同日唯一与覆盖

同一天永远只对应一条：
- 应用自动保存（每完成一轮专注）= 写当日 `facts`；
- 当日点评 / 周报解读成功 = 把 `note` / `insight` 合并进**同一条**；
- 因此「当日多次写」的结果是**一条不断被更新的日记忆**，不是多行流水。

### 5.2 字段级所有权（外部写入者的核心保障）

应用重写当日条目时**只覆盖应用拥有的键**（§4.1 中标「应用」的那些）。
其余键（含 `memory`）**原样带过**。

于是：
- 外部程序写进 `memory` 的记忆，**不会被应用的下一次自动保存冲掉**；
- 外部程序也可以只写 `memory` 而完全不写 `facts`——应用之后补上，两边互不干扰。

### 5.3 外部写入建议

- 只需 `date` 一个必需字段；建议顺手带 `schema` / `rev` / `updated_at`，便于对账；
- 传记忆写 `memory`（字符串，建议 ≤200 字，注入时会截断到 60 字，见 §7）；
- **不要**尝试改 `facts` / `note` / `insight`——应用会在下一次保存时覆盖它们；
- 想改「注入什么」，改 `memory`：它在注入时排在应用自己的 `note` 之后、优先级最高。

---

## 6. 容错口径（务实优先）

| 情况 | 行为 |
| --- | --- |
| 缺 `schema` / `rev` / `updated_at` | **不判非法**，按无 schema / `rev=1` / 空时间解析 |
| `date` 缺失或非 `yyyy-MM-dd` | 该行判为非法行，原样保留在文件末尾 |
| 非 JSON / 非对象 | 同上 |
| 同日多条 | 后出现者胜出，写回时归一为一条 |
| 未来日期 | 解析保留，但**不进入任何窗口**（防外部程序预先写好被误当历史） |
| 文件不存在 | 视为空日志（应用首次写入时创建） |
| 读取抛异常 | 视为「无记忆」，**不影响 AI 解读主链路**（记忆是增强项） |
| 数字写成 `210.0` / `"210"` | 宽容取整，不判非法 |

---

## 7. 读取与注入规则（本机 AI 实际看到什么）

1. **窗口**：近 7 日，**不含当日**。当日数字已经在事实块里，两边都注入就会出现
   「同一份数据两个口径」——08-A1 已经付过一次代价。
2. **注入内容**：每行 = `date` + `facts` 摘要 + `note` + `memory`。
   `insight` **不注入**（周报全文 7 天会挤爆 token 预算），它留在文件里供外部程序读取。
3. **截断与上限**：
   - 单条 `note` / `memory` 截断到 **60 字**（超出加 `…`）；
   - 整块上限 **900 字**，超出时**丢掉更早的条目**（宁要近 3 天完整，不要 7 天残缺），
     且至少保留最近一条；
   - 空条目（既无 `facts` 又无文本）不占预算。
4. **注入位置**：user message 内、**事实块之后、任务指令之前**。
   任务指令留在末位（模型对末位指令遵循度最高），记忆作为背景夹在中间。
5. **配套约束**：system 硬约束第 10 条明确「记忆里的数字属于过去，
   不要拿来当本次数据，也不要与本次数据混算」。
6. **注入块表头**（固定文案，外部程序可据此在抓包里认出记忆段）：

   ```
   【近 7 日记忆】（本地记忆日志，仅供参考：其中的数字属于过去，不要拿来当本次数据，也不要与本次数据混算）
   ```

7. **无记忆时**：user message 与未引入本功能时**逐字符一致**（记忆是增强，不是必需）。

## 8. 外部程序怎么用

### 8.1 写记忆（把别处的上下文递给本机 AI）

```python
import json

PATH = "/sdcard/Android/data/com.aiclock.player/files/mikufocus_ai_memory.jsonl"
TODAY = "2026-09-26"

def upsert(date: str, **fields):
    """按 date 合并一行；已有该日期则原地更新，其余键原样保留。"""
    lines, found = [], False
    try:
        with open(PATH, encoding="utf-8") as f:
            lines = [l for l in f.read().splitlines() if l.strip()]
    except FileNotFoundError:
        pass
    out = []
    for l in lines:
        try:
            obj = json.loads(l)
        except json.JSONDecodeError:
            out.append(l)          # 坏行原样留着，不要丢
            continue
        if obj.get("date") == date:
            obj.update(fields)
            l, found = json.dumps(obj, ensure_ascii=False), True
        out.append(l)
    if not found:
        out.append(json.dumps({"schema": "aiclock.ai_memory/1", "date": date,
                               **fields}, ensure_ascii=False))
    out.sort(key=lambda s: (json.loads(s)["date"] if s.startswith("{") else "\uffff"))
    with open(PATH, "w", encoding="utf-8") as f:
        f.write("\n".join(out) + "\n")

# 传一条记忆：下次请求（点「AI 解读」/「问 AI 一句」）就会带上
upsert(TODAY, memory="最近在赶论文，夜里效率反而高。", source="pc-script")
```

### 8.2 读 AI 的结论

读 `note`（当日点评）与 `insight`（周报解读）两列即可——
它们就是本机 AI 在这个设备上「说过的话」。`facts` 是它当时的依据。

### 8.3 对账

`rev` / `updated_at` / `prompt_version` 三个字段足以回答
「这条是什么时候、由哪一版提示词写出来的」。

## 9. 隐私边界（务必先读）

**写进日志的东西，可能被发出去。**

- 记忆日志的近 7 日会随每一次 AI 请求发送给用户选择的服务商
  （设置 → AI 功能 → 数据使用说明 v2 已如实披露）；
- 因此**不要把不想外发的内容写进 `memory`**：它没有本地过滤，写进去就会随请求外发；
- 应用自身写入的内容限定在 §4.2 白名单 + AI 自己的输出，**不含钟点、应用名、内容维度**；
- 关闭 AI 总开关后：**不读、不写、不注入**（记忆日志只服务于 AI 联动，
  关掉的功能不在设备上留痕迹）；
- 「删除 AI 数据」会一并清空本文件（US-AI-D04：删除 = 彻底离开）；
  清空后外部程序仍可继续写入。

## 10. 版本与兼容

- `schema` = `aiclock.ai_memory/1`。**主版本**变化才意味着结构不兼容；
- 新增字段一律是**可选键**，旧读取方忽略即可；应用写出的键只增不减；
- 应用遇到不认识的主版本时**尽力解析**（字段级校验仍生效），
  解析不了的行按 §6 原样保留——**不会因为版本不同就清空别人的数据**；
- 提示词版本 `prompt_version` 与 `kPromptVersion` 同步，
  它是「这条记忆是哪一版 AI 写的」的标记，不影响格式兼容性。

---

## 11. 与其它机制的边界

| 机制 | 存哪 | 用途 | 是否上传 |
| --- | --- | --- | --- |
| 记忆日志（本文档） | 外存 JSONL | 跨程序记忆 + 近 7 日注入 | **是**（近 7 日随请求） |
| 解读/点评缓存 | SharedPreferences | 同周/同日回看零请求 | 否 |
| 上传快照 `ai_last_upload_json` | SharedPreferences | 逐字段核对「实际发出去什么」 | 否（它是记录，不是数据源） |
| 专注记录备份 | 外存 JSON | 数据导出/导入 | 否 |

记忆日志**不是**备份：它只保留每天一条的摘要，且随时可被清空。

## 12. 验收要点（代码化在 `test/memory_log_test.dart`）

- [x] 乱序输入 → 输出按 `date` 升序；同日重复 → 后写胜出
- [x] 坏行（非 JSON / 非对象 / `date` 非法）→ 计数并原样保留，不整文件报废
- [x] BOM / CRLF 可读；`note` 内的换行不破坏「一行一条」
- [x] 同日写入 → `rev` +1、应用字段覆盖、**外部键（含 `memory`）保留**
- [x] 近 7 日窗口：含当日 = `[今天-6, 今天]`；不含当日 = `[今天-7, 今天-1]`；未来不入选
- [x] 注入块：`facts`/`note`/`memory` 三类都在，`insight` 不注入，超预算保最近的
- [x] 单条文本截断到 60 字；零值（完成 0 个 / 中断 0 次）不啰嗦
- [x] 无记忆时 user message 与未引入本功能时逐字符一致
