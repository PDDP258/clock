## 1. 定位与挂载方式

AI 模块是挂在既有四层架构上的**增量 Feature 插件**（ADR-0003），不改动核心链路：

```
┌──────────────────────────────────────────────────┐
│ Feature 功能层                                    │
│  focus · stats · usage · settings · ai(新增)     │
├──────────────────────────────────────────────────┤
│ Core 核心层（纯 Dart）                            │
│  + insight/  洞察引擎（本地规则，纯 Dart 可测）    │
│  + ai/       PromptBuilder · LlmProvider 接口     │
├──────────────────────────────────────────────────┤
│ Platform 适配层                                   │
│  + http/       云端 LLM HTTPS 客户端              │
└──────────────────────────────────────────────────┘
```

**关键分工**：数字与洞察判定全部在本地（Core 层纯 Dart），云端 LLM 只做自然语言润色。AI 任一环节失效，计时与统计零影响。

## 2. 数据流

```
drift 统计表（focus_session / usage_stat_daily）
   │
   ▼
InsightEngine（本地规则，纯 Dart）
   │   复用 weekly_report / focus_heatmap /
   │   focus_interruption / elastic_streak
   ▼
结构化洞察 JSON（仅存本地；含环比、时段分布、
                弹性连续天数、Top 中断来源=匿名类别）
   │
   ├──────────────────── 默认止步于此 ──────────────────┐
   ▼                                                    ▼
[用户点击「AI 解读」]                          统计页结构化周报（现有能力，
   │                                            无网/无 Key 时始终可用）
   ▼
PromptBuilder（白名单字段 → prompt）
   │
   ▼
LlmProvider（HTTPS，首选 DeepSeek，超时 15s）
   │
   ▼
解读文案（≤3 段复盘 + 1 条建议）→ 缓存本地，可回看
```

## 3. LlmProvider 接口定义（草案）

Core 层纯 Dart 抽象，业务只依赖接口：

```dart
/// 云端 LLM 服务商抽象：首选 DeepSeek，可换 Kimi / 通义千问。
/// 契约：只做自然语言润色；任何失败都必须可降级，不得抛穿业务层。
abstract class LlmProvider {
  /// 服务商标识（deepseek / kimi / qwen）
  String get id;

  /// 由 prompt 生成解读文案。
  /// 超时：连接 10s + 读取 15s；超时按 [LlmFailure.timeout] 处理。
  /// 返回 null 表示不可用（未配置 Key）；失败统一抛 [LlmFailure]，
  /// 调用方一律捕获并降级为结构化周报。
  Future<String> generateInsight(String prompt);

  /// 连通性自测（设置页「测试 Key」用）：成功返回 true。
  Future<bool> ping();
}

/// 失败分类：network / timeout / unauthorized / quota / badResponse。
/// 除 unauthorized/quota 在 UI 给一行提示外，其余静默降级。
sealed class LlmFailure implements Exception { /* … */ }
```

要点：

- **降级是接口的一等公民**：`generateInsight` 的所有失败路径都有明确定义，调用方（统计页）只面对「文案 or null」；
- **重试克制**：失败不自动重试（用户主动触发 = 手动重试），避免无网时抖动；
- **Key 存储**：API Key 存 shared_preferences（现有配置通道），不日志、不上报、不经 AnalyticsSink。

## 4. Prompt 契约

> 2026-09-25 优化轮（[08-AI功能优化建议](./08-AI功能优化建议.md)）：角色与硬约束迁到 `system` 消息（08-A5），
> 事实块收敛为 `weeklyFactsBlock` / `dailyFactsBlock` 单一来源（08-B2），
> token 预算按任务分档（08-A4），并补 `days_elapsed` 如实声明「部分周」（08-A1）。
>
> 2026-09-26 调性轮（看板 #53）：洞察扩 8 个字段（08-B3）、硬约束拆成
> 「禁空洞 / 要具体」两组、采样温度 0.3 → 0.6、缓存指纹并入 `kPromptVersion`。
>
> 2026-09-26 记忆轮（看板 #54）：新增**跨程序记忆日志**并注入近 7 日
> （[09-AI记忆日志规范](./09-AI记忆日志规范.md)）；硬约束补第 10 条「记忆不得混算」；
> 当日事实块**去掉钟点**（见 §4.3）；`kPromptVersion` → `v3`。

### 4.1 输入 schema（PromptBuilder 产出，白名单字段）

| 字段 | 来源 | 示例 |
| --- | --- | --- |
| `week_focus_minutes` / `last_week_focus_minutes` | weekly_report（后者为**上周同期**基线：上周一至与本周相同的进度点，08-A1） | 620 / 540 |
| `days_elapsed` | weekly_report（本周已过天数，周一=1） | 3 |
| `change_ratio` | weekly_report（上周同期无基线为 null，prompt 中不给数字也不给对比，不误导） | +0.15 |
| `session_count` / `rounds` | weekly_report / focus_session 聚合 | 21 / 17 |
| `slot_distribution` | weekly_report 四桶 + focus_heatmap | 上午 45% / 下午 30% / 晚上 25% |
| `streak_days` / `buffer_used` | elastic_streak | 5 天 / 已用缓冲 1 天 |
| `interruption_count` / `interruption_minutes` | focus_interruption（专注内暂停，US-D02 以暂停区间替代切出检测） | 6 次 / 32 分钟 |
| `interruption_slot_distribution` | 同上，**按次数**归入四桶（未闭合暂停没有时长，用次数才不漏计） | 晚上 67% / 下午 33% |
| `interruption_ratio` / `avg_interruption_minutes` | 本地算好的占比与单次均值，一次算好，LLM 不必自己做除法 | 0.052 / 5 |
| `longest_segment_minutes` / `longest_segment_slot` | focus_session 单段最大 + 其起始时段 | 50 / 下午 |
| `best_day_label` / `best_day_minutes` | 按本地自然日聚合取最大 | 周三 / 240 |
| `active_days` | 本周有专注记录的天数 | 3 |

> **2026-09-26（看板 #53）新增 8 个字段**（`interruption_slot_distribution` 起至 `active_days`），
> 全部为**时段/时长聚合**，与 `slot_distribution` 同性质，无应用名、无内容维度；
> 对应的原始数据（暂停时间戳、单段长度、会话日期）此前就在库里，只是没被聚合进洞察。
> 新增目的：让 LLM 手里有**可互相比较的数字**，才可能说出「关系」而非复述总量。
>
> `top_interruption_categories`（PRD 原案）**不存在**——US-D02 落地时以暂停区间替代了
> 应用维度，drift 里没有应用类别数据（AGENT.md §7 已记录该偏差），本轮同步从表中移除。

**不上传但本地使用**：`WeeklyInsight.dataFingerprint` / `DailySummary.dataFingerprint`
（会话数 + 分钟数 + 轮数 + 中断数的拼接串），与提示词版本（`kPromptVersion`）拼成
缓存比对指纹，只用于判断本地缓存解读是否已过时（08-A2 / 看板 #53），
不进入 `toUploadJson()`，有单测锁定其不出现在上传体。

**消息结构**：`system` = 角色 + 10 条硬约束（分三组：数字纪律 / 禁止空洞 / 要求具体 +
格式条款 + 记忆引用），`user` = 白名单事实块 +（可选）近 7 日记忆 + 本次任务。
硬约束分组的理由见 08 §10：
**「禁」只禁没有信息量的表达，不禁有性格的表达**——08-A5 那版只有「禁」没有「要」，
模型于是选择了最安全的写法（照事实块逐行复述），这正是用户反馈「枯燥」的直接来源。
四类任务的 token 预算：周报 600 / 问答 200 / 当日点评 120；采样温度 0.6。

**记忆注入块（看板 #54）**：由 `core/ai/memory_log.dart` 渲染，取自本机记忆日志
（近 7 日、**不含当日**——当日数字已在事实块里，两边都注入就会出现两个口径）。
每行 = 日期 + `facts` 摘要 + `note` + 外部写入的 `memory`；单条截断 60 字、整块上限 900 字，
超出时丢掉更早的条目。位置固定在**事实块之后、任务指令之前**（任务留在末位遵循度最高）。
格式与外部写入规范见 [09-AI记忆日志规范](./09-AI记忆日志规范.md)。
无记忆时 user message 与未引入本功能时**逐字符一致**（记忆是增强，不是必需）。

### 4.2 输出契约

- **≤3 段自然语言复盘** + **恰好 1 条可执行建议**；
- **第一句必须是「发现」而非「概述」**（看板 #53）：要写出数字之间的关系
  （时段互比 / 本周与上周同期比 / 最长与平均比 / 中断集中在哪一段），
  不允许复述用户一眼就能看到的总量；同时允许比喻与短句——约束的边界是
  「每句话都对得回数字」，不是「语气必须中性」；
- 只允许基于输入数字陈述，**不得编造数字**；system 消息中显式声明「所有数字必须原样引用输入」；
- 响应解析（`core/ai/response_parse.dart`）为**加固层**：按空行切段、无空行时回退按单行切段；
  「建议」段允许 Markdown 装饰（`**建议：**` / `- 建议：` / `## 建议：`）与前导装饰；
  复盘段落自动去 Markdown；问答/点评跳过模型客套开场白（「好的，根据你的数据：」）。
  超过 3 段截断；确无建议段才整体降级，不展示半截乱文。

### 4.3 匿名化

- 中断来源在 `focus_interruption` 输出层即做**应用名 → 类别**映射（社交/视频/工具/其他），类别标签才允许进入洞察 JSON；
- 设备标识（IMEI / Android ID / MAC）不出现在任何上传内容中；
- 原始事件流（逐次会话起止明细）**永远不上传**；语音功能已砍（ADR-0006），无任何音频数据上传面；
- **不含钟点**（2026-09-26 修正，看板 #54）：当日事实块原先带一行
  `- 起止：从 09:12 到 18:40`，与本节第 3 条及设置页数据使用说明的
  「不发送具体时间点」相矛盾——模型看得见的东西就是发出去了的东西。
  现已移除，当日粒度只保留时长/轮数/段数/时段桶（`dailyFactsJson` 单一来源），
  并有单测断言事实块与上传快照都不含 `HH:mm`；
- **记忆日志是用户可控的上传面**：近 7 日记忆会随请求外发，
  其中可能包含外部程序写入的 `memory` 内容。设置页数据使用说明已升到 v2 如实披露，
  并提供「查看/清空记忆日志」入口。原则是**披露而不是静默过滤**：
  用户自己写进去的上下文，只有用户能判断该不该发。

## 5. 隐私技术设计

### 5.1 上传白名单（唯一允许出设备的字段表）

上传内容 = §4.1 表中的字段 + §4.1 的记忆注入块，且仅此两者。实现上以**显式序列化**保证：洞察 JSON 由手工列字段的 `toUploadJson()` 产出（而非反射整对象），新增字段默认不进上传体——从代码结构上防泄漏，并有单测做脏数据扫描（见 [06-Testing Decisions](./06-AI功能PRD.md)）。

记忆注入块的字段来源同样受约束：应用写入部分只含 §4.2 白名单聚合量，
外部程序写入的 `memory` 属于**用户自行提供的上下文**，已在同意文案中披露（见 §4.3）。
两类内容都逐字进入「查看实际上传字段」的快照（`memory_block` 键），可逐字段核对。

### 5.2 同意记录落库

- 数据使用说明的**单独同意**记录（同意时间、说明文案版本号）持久化于 shared_preferences；撤销同意（关闭总开关）即记录撤销并停止一切云端请求；
- 当前文案版本 `v2`（2026-09-26 补记忆日志披露，看板 #54）；
- 设置页提供「查看实际上传字段」入口：展示最近一次请求的完整上传 JSON（含 `memory_block`），逐字段可核对（US-AI-A04）；
- 设置页提供「跨程序记忆日志」入口：文件路径、条目数、近 7 日预览与清空（长按/选中可复制路径）；
- AI 数据删除：解读缓存、同意记录、上传快照、**记忆日志文件**可一键删除（US-AI-D04）。

## 6. 降级矩阵

| 场景 | 行为 | 用户感知 |
| --- | --- | --- |
| 无网 | 「AI 解读」点击后显示现有结构化周报 + 一行「当前离线，仅展示本地统计」 | 功能完整可用，无错误弹窗 |
| 未配置 API Key | 同上，提示行引导「去设置页配置 Key」（可关） | 结构化周报始终完整 |
| 请求超时 / HTTP 错误 | 静默降级为结构化周报 + 一行可重试提示 | 无阻断、不自动重试 |
| 响应解析失败 / 超长 | 截断至契约内（≤3 段+1 建议）；无法截断则整体降级为结构化周报 | 永不展示半截乱文 |

补充：云端 LLM 是 AI 模块唯一外部依赖；本地 InsightEngine 纯 Dart 运行，任何网络状态下结构化周报与洞察 JSON 均可产出。

## 7. 功耗预算

| 项 | 预算 | 说明 |
| --- | --- | --- |
| 云端请求 | 忽略 | 每周一次、千级 token、单次 HTTPS；仅用户主动点击触发 |
| 本地 InsightEngine | 忽略 | 纯 Dart 规则计算，输入为本地统计聚合结果，数据量小 |
| 解读缓存 | KB 级 | 每周最多一条解读文案本地缓存，随「删除 AI 数据」清空 |

AI 模块无原生依赖、无常驻服务、无后台任务——计时链路的功耗 profile 与 V0.4 完全一致。

## 9. 风险登记册（AI 新增项，续接 03 §10）

| # | 风险 | 等级 | 说明与缓解 |
| --- | --- | --- | --- |
| R9 | **LLM 服务商可用性/成本波动** | 低 | DeepSeek 涨价、停服或 Key 失效只影响解读润色；LlmProvider 抽象可换 Kimi/通义，降级矩阵（§6）保证核心功能零损失。 |
| R10 | **隐私白名单回归泄漏** | 中 | 洞察 JSON 新增字段若误入上传体即违反最小化承诺。缓解：显式 `toUploadJson()` 白名单序列化（新增字段默认不上传）+ PromptBuilder 脏数据扫描单测（见 [06-Testing Decisions](./06-AI功能PRD.md)）。 |
| R11 | **API Key 分发与滥用** | 低 | MVP「用户自备 Key」规避；若未来内置代理 Key，需限流与用量封顶，另立决策。 |
