## Problem Statement

V0.4 之后，用户每周能在统计页看到结构化周报（本周总量、环比、最专注时段、热力图、中断分析），但**数字不会自己说话**：用户需要自行解读「环比 -15% 意味着什么、下周该怎么调整」。这是市场调研痛点 Top7「统计浅、只管计时，缺乏复盘闭环」在 V0.4 之后的残留部分——数据有了，解读缺位。

与此同时，调研（[05 §2.3](./05-AI功能调研报告.md)）表明用户对 AI 的态度高度分化：**反感打扰型 AI**（主动弹窗/推送/喧宾夺主，微软 Copilot 广告被抵制、61% 员工担忧「AI-maxxing」），**接受安静型 AI**（安静省时、结果一眼可验证）。而 ADR-0005 曾以「功能堆叠」为由砍掉 AI 专注建议——该砍掉针对的是打扰式/堆叠式 AI，并未否定「安静解读已有数据」这一形态。

用户真正需要的是：**在已经产生的专注数据之上，有一层按需取用的解读**——想看时点一下，得到一段人话复盘和一条可执行建议；不想看时 AI 完全不存在，计时、统计、离线可用性一切照旧。

## Solution

**一句话定位：AI 模块 = 已有专注数据的「增值解读层」，不是新交互入口。** 唯一功能：

**AI 周报解读（V0.5）**——本地洞察引擎（复用 weekly_report / focus_heatmap / focus_interruption 数据，纯 Dart 规则计算）产出结构化洞察 JSON → 用户在统计页**主动点击**「AI 解读」→ 云端 LLM（首选 DeepSeek，可换 Kimi/通义）生成自然语言复盘 + **一条**可执行建议。无网/未配置 Key 时退化为现有纯结构化周报——LLM 只做润色，核心功能永不受 AI 可用性影响。

> 2026-08 月 27 日所有者决策：语音类功能（TTS 语音播报、语音速记，曾列为 V0.5/V0.6）全部砍掉，专注单一云端路线、降低硬件联调风险；端侧 ASR/TTS 调研结论在 [05](./05-AI功能调研报告.md) 留档备查，取舍记录见 [ADR-0006](./adr/0006-ai-features-scope.md)。

### AI 安静原则（核心约束，红线）

> **AI 永不在计时进行中发声/弹窗/主动推送建议；AI 输出只在用户主动查看处呈现；设置页提供一键全局关闭 AI 的开关；AI 功能全部默认关闭，需用户主动开启并单独同意数据使用说明。**

该原则是 ADR-0005「简洁为主、体验第一」在 AI 功能上的延伸（见 [ADR-0006](./adr/0006-ai-features-scope.md)）。任何 AI 需求与安静原则冲突时，以安静原则为准。

### 隐私底线

只上传匿名聚合统计（周时长、次数、时段分布、弹性连续天数、中断来源的匿名类别），剥离设备标识；不上传原始事件流和应用名明细；单独同意；默认离线可用（依据见 [05 §5](./05-AI功能调研报告.md)，字段级清单见 [07-技术方案](./07-AI功能技术方案.md)）。

## User Stories

> 每条标注所属版本（V0.5 / 远期）。「远期」为实验项，不承诺进路线图。

### A. AI 周报解读（V0.5）

1. **US-AI-A01（V0.5）** 作为用户，我希望在统计页周报卡片上看到「AI 解读」按钮，**主动点击后**才生成解读，以便 AI 只在我要看时出现。
2. **US-AI-A02（V0.5）** 作为用户，我希望解读内容是一段不超过 3 段的自然语言复盘，外加**一条**具体可执行的下周建议，以便快速看懂数据并知道怎么改。
3. **US-AI-A03（V0.5）** 作为用户，我希望在无网、未配置 API Key 或请求失败时，周报仍完整显示现有结构化内容（总量/环比/时段/热力图/中断分析），以便核心复盘能力永不掉线。
4. **US-AI-A04（V0.5）** 作为用户，我希望在隐私说明页看到本次上传了哪些字段（逐项列出实际值），以便对「我的数据去了哪」一目了然。
5. **US-AI-A05（V0.5）** 作为用户，我希望同一份周报的解读结果缓存在本地、可回看且不重复请求云端，以便节省 token 并支持离线回看。

### D. 控制与隐私（V0.5）

14. **US-AI-D01（V0.5）** 作为用户，我希望设置页有「AI 功能」区并提供**一键全局关闭 AI** 的总开关，以便反悔成本为零。
15. **US-AI-D02（V0.5）** 作为用户，我希望所有 AI 功能**默认关闭**，开启时单独展示并让我同意数据使用说明，以便知情授权、不被默认勾选。
16. **US-AI-D03（V0.5）** 作为用户，我希望计时进行中 AI 永不发声、弹窗或推送建议（AI 安静原则），以便专注不被打扰。
17. **US-AI-D04（V0.5）** 作为用户，我希望能随时查看并删除 AI 相关数据（同意记录、解读缓存、速记文本），以便掌控自己的数据。

### E. 远期实验项

18. **US-AI-E01（远期，不承诺）** 作为用户，我希望中断原因能被端侧 1B 级小模型自动打标/分类（对延迟不敏感、无对话能力要求），以便中断分析更智能——**仅在端侧推理实测达标后另行评估立项**。

## Implementation Decisions

### 1. 插件化目录：`lib/features/ai/`

按 Feature-first 插件化架构（ADR-0003）新增 `feature_ai` 模块，目录 `lib/features/ai/`，当前以 [AI_MODULE.md](../lib/features/ai/AI_MODULE.md) 预留说明先行。模块自含 UI（统计页「AI 解读」入口、设置页「AI 功能」区）/ Provider / 服务绑定，版本裁剪 = 增删目录 + 装配层一行注册；**AI 总开关关闭时，UI 入口整体隐藏**。

### 2. LlmProvider 抽象接口

Core 层定义抽象（接口草案见 [07-技术方案 §3](./07-AI功能技术方案.md)）：

- 首选实现 **DeepSeek**（最便宜，新用户赠 500 万 token，[05 §4](./05-AI功能调研报告.md)）；
- 可替换实现 Kimi、通义千问——切换只改设置，不改业务代码；
- 统一超时与错误降级约定：任何失败都静默退化为结构化周报，不弹错误阻断用户。

### 3. PromptBuilder：结构化统计 → Prompt

纯 Dart 组件：输入本地洞察引擎产出的结构化洞察 JSON（周时长、次数、时段分布、弹性连续天数、Top 中断来源的匿名类别），按固定模板拼装 prompt（输入 schema 与输出契约见 [07-技术方案 §4](./07-AI功能技术方案.md)）。**数字由本地规则引擎算好，LLM 不得自行计算或编造数字**——输出只允许基于给定数字的复盘与建议。

### 4. 隐私最小化上传清单

| 上传 | 不上传 |
| --- | --- |
| 本周/上周专注总时长、环比 | 原始事件流（逐次会话起止明细） |
| 专注次数、完成轮数 | 应用名明细（中断来源只传匿名类别） |
| 时段分布（凌晨/上午/下午/晚上 四桶占比） | 设备标识（IMEI/Android ID/MAC 一律剥离） |
| 弹性连续天数 | 任何语音数据（语音功能已砍，无此类数据） |
| Top 中断来源的匿名类别标签 | 任何未列于左表的字段 |

字段级白名单表与匿名化实现见 [07-技术方案 §5](./07-AI功能技术方案.md)。

### 5. 设置页「AI 功能」区

- **总开关**：一键全局关闭 AI（关闭后隐藏全部 AI 入口、停止一切云端请求）；
- **API Key 配置**：DeepSeek Key 输入与连通性自测；服务商切换（DeepSeek/Kimi/通义）；
- **隐私说明**：数据使用说明 + 单独同意记录 + 「查看实际上传字段」入口 + 删除 AI 数据。

### 6. 与现有 weekly_report 的复用关系

洞察引擎**直接复用** stats 域已有组件，不重复造轮子：

- `weekly_report.dart`（本周总量、上周环比、最专注时段）→ 洞察 JSON 的主干字段；
- `focus_heatmap.dart`（专注热力图）→ 时段分布与规律性判定；
- `focus_interruption.dart`（中断分析）→ Top 中断来源（输出前匿名化为类别标签）；
- `elastic_streak.dart`（弹性连续）→ 连续天数与断签缓冲状态；
- `session_record.dart`（core/timer）→ 会话级事实来源。

**分工**：洞察引擎（本地、纯 Dart、可单测）负责「算什么、判断什么」；LLM（云端）只负责「怎么说」。无 LLM 时现有结构化周报照常工作——AI 是增量渲染层，不是数据层依赖。

## Testing Decisions

1. **洞察引擎纯 Dart 单测**：复用 core/stats 的 fake clock 模式，覆盖周报为空、上周无基线、环比正负、时段四桶边界、中断来源匿名化映射等路径；输出必须是合法结构化 JSON（schema 校验）。
2. **PromptBuilder 纯 Dart 单测**：断言 prompt 包含且仅包含白名单字段；断言不含应用名/设备标识/原始事件（对构造的脏数据做泄漏扫描）；断言输出契约（≤3 段复盘 + 1 条建议）的解析与超长截断。
3. **LlmProvider mock 测试**：以 fake HTTP client 覆盖成功解析、超时、HTTP 错误、返回格式非法四类分支，断言每类都静默降级为结构化周报且无未捕获异常。
4. **断网降级测试**：飞行模式下「AI 解读」按钮点击 → 结构化周报完整呈现 + 一行降级提示；无 Key、Key 失效、请求超时、返回解析失败四种场景逐一验证行为符合降级矩阵（[07 §6](./07-AI功能技术方案.md)）。
5. **安静原则回归测试**：计时进行中模拟 AI 事件（解读完成回调），断言无任何弹窗/声音/通知；AI 总开关关闭后断言全部 AI 入口隐藏且零网络请求。

## Out of Scope

- **语音播报、语音速记、端侧 ASR/TTS**（所有者决策 2026-08-27 砍掉：专注单一云端路线、降低硬件联调风险；调研结论在 [05 §3.2](./05-AI功能调研报告.md) 留档备查）
- **端侧 LLM 对话**（骁龙 680 上不可行，实测依据见 [05 §3.1](./05-AI功能调研报告.md)；1B 级打标/分类仅列为远期实验项，不承诺）
- **AI 主动推送 / 打扰式 AI**（违反 AI 安静原则；ADR-0005 砍掉「AI 专注建议」的精神在此保留——主动给建议永远不做，用户主动点的解读才做）
- **排程自动化**（Motion 式全自动排程：与「设备在计时期间消失」的理念冲突，M500 无日历生态承接，见 [05 §2.2](./05-AI功能调研报告.md)）
- **多模态**（拍照识屏、图像理解等与自律计时无关的能力）
- **AI 参与计时决策**（LLM 不得影响计时、统计、按键等核心链路；AI 不可用 = 产品零损失）
