## 1. 架构总览

采用四层架构，依赖方向自上而下，**下层不依赖上层**：

```
┌─────────────────────────────────────────────────┐
│ App 装配层 (app)                                 │
│  main.dart / 路由 / 主题 / DI 容器组装 / 引导流程 │
├─────────────────────────────────────────────────┤
│ Feature 功能层 (features/*)                      │
│  focus · stats · usage · settings · sync(预留)  │
│  （blocker/goals/gamification 已砍，ADR-0005）  │
├─────────────────────────────────────────────────┤
│ Core 核心层 (core/*) —— 纯 Dart，无 Flutter 依赖  │
│  timer(计时引擎) · media_keys(按键解析与Command)  │
│  domain models · repository 接口 · AnalyticsSink  │
├─────────────────────────────────────────────────┤
│ Platform 适配层 (platform/*)                     │
│  audio_service 封装 · usage_stats 封装 ·          │
│  通知/前台服务 · drift 数据库 · 权限引导           │
└─────────────────────────────────────────────────┘
```

设计约束：

- **Core 层纯 Dart**：计时引擎与按键解析不 import Flutter，可直接 `dart test` 单测（对应 [PRD-Testing Decisions](./02-PRD-产品需求文档.md)）。
- **Feature 层插件化**：每个 feature 独立目录、独立 Provider 注册点，可按版本/渠道裁剪（ADR-0003）。
- **Platform 层可替换**：所有系统能力经抽象接口注入，真机实现与 fake 实现并存，支撑外部行为测试。

## 3. 状态管理选型：Riverpod

- 编译期安全、可覆盖（override）特性天然适配「真机实现 / fake 实现」切换与 feature 插件注册；
- `StreamProvider` 直接对接 drift 流式查询（ADR-0002），统计页数据变更自动刷新；
- 按键事件流（Platform → Core Command → Feature 状态）用 `StreamProvider` + `Notifier` 组合表达，链路清晰可测。

## 4. 计时引擎设计（core_timer）

### 4.1 计时原理：时间戳差值，而非每秒累加

- 引擎只记录**锚点时间戳**：`phaseStartEpochMs`、`accumulatedPauseMs`、`pauseStartEpochMs?`；
- 剩余时间 = `phaseDuration - (now - phaseStart - accumulatedPause)`，`now` 来自注入的 `Clock`（生产环境 `DateTime.now()`，测试用 fake）；
- UI 的每秒刷新只是对差值的渲染，不参与计量。**熄屏、杀进程、系统休眠均不影响计量准确性**，恢复后用当前时间与锚点重算即可。
- **明确拒绝每秒轮询计时**：第三方规划报告采用的 flutter_foreground_task `repeat(1000)` 每秒唤醒方案费电、在 Doze/后台限制下不可靠，且把「计量」与「渲染刷新」错误耦合（刷新一断计时就漂）。本方案以时间戳差值计量、注入 `Clock` 假时钟可测（评审见 [04-批判评审](./04-批判评审与方案优化.md) §2.2）。

### 4.2 状态机

```
        ┌──────────┐  start   ┌───────────┐
        │   idle   │─────────▶│ focusing  │◀────────┐
        └──────────┘          └───────────┘         │
              ▲                 │  │  │             │
              │            pause│  │  │phase end    │next phase
              │                 ▼  │  ▼             │
              │              ┌────────┐   ┌───────┐ │
              │              │ paused │   │ break │─┘
              │   end/abort  └────────┘   └───────┘
              │                 │              │
              │                 │resume        │phase end
              │                 ▼              ▼
              │            (回 focusing)  ┌───────────┐
              └───────────────────────────│ completed │
                     abort 亦可直达        └───────────┘
```

状态：`idle → focusing → paused → break → completed`（含 `aborted` 终态）。每次状态迁移写入持久化存储（见 4.3），迁移即产生一条不可变事件，统计与复盘基于事件流计算。

### 4.3 持久化防杀恢复

- 每次状态迁移（开始/暂停/继续/阶段切换/结束）立即将「当前状态 + 全部锚点时间戳 + 会话元数据」写入 drift `focus_session` 表；
- App 冷启动时读取「未完结会话」，用当前时间重算阶段位置：仍在有效期内 → 恢复并补发前台服务与通知；已过期 → 按配置自动结算或询问用户；
- 4500mAh 电池 + 封闭定制 ROM 使长时计时被杀概率低，但恢复机制作为兜底必须存在（对应 US-C01）。

## 5. 媒体按键链路设计（core_media_keys + platform/media_session）

> 决策依据见 [ADR-0001](./adr/0001-audio-service-media-session-hijack.md)。

### 5.1 M500 按键输入特性（与蓝牙耳机方案的本质差异）

- 侧边实体按键**主板直连**，走 Android 标准 KeyEvent 通道，出厂映射：`PLAY_PAUSE=85`、`NEXT=87`、`PREVIOUS=88`；
- **本地直连、可靠到达**：原方案中「部分蓝牙耳机仅在 playing 态上报 next/prev」的 AVRCP 到达率风险**在本硬件上不存在**；
- 但 **MediaSession 仍需保持 active**：按键事件由系统媒体路由分发，只有持有活跃媒体会话（且音频焦点）的 App 才能在后台/熄屏时收到按键——静音保活机制因此保留。

> **对「M500 按键主板直连，因此不需要 audio_service」论点的正式驳斥**（第三方规划报告 v1.1 的主张，评审见 [04-批判评审](./04-批判评审与方案优化.md) §2.1）：
> 直连 GPIO 只解决**事件来源**（按键事件本地可靠产生），不解决**事件路由**——熄屏/后台时，系统只把媒体键分发给持有 active MediaSession 的 App；没有活跃会话，按键事件根本不会到达本 App。而 audio_service 恰好免费提供了这一整条管道：MediaSession 管理 + `mediaPlayback` 类型前台服务（Android 14 合规）+ 锁屏/通知（MediaStyle）集成。手写裸 MediaSession + flutter_foreground_task 是重复造轮子，且在音频焦点竞争、会话释放、后台回收等边角上更容易出 bug。**维持 ADR-0001 决策不变。**

### 5.2 链路结构

```
实体按键 (KeyEvent 85/87/88)
   │
   ▼
Android MediaSession 路由 ──(audio_service, androidForceEnableMediaButtons)
   │
   ▼
静音保活播放器（播放静音音频，保持 session active + FGS mediaPlayback）
   │
   ▼
KeyEvent 解析器：800ms 窗口多击计数（单/双/三按）
              + ACTION_DOWN/UP 时长长按判定
   │
   ▼
语义回调 → Command 映射层（key_command_mapper，可配置持久化）
   │
   ▼
Command（start/pause/resume/plus5min/skip/end/undo）→ timer_engine
```

### 5.3 会话霸占 / 释放策略（与音乐 App 的仲裁——M500 特有问题）

M500 本职是音乐播放器，按键归属必须显式管理（对应 PRD Implementation Decisions 第 4 节）：

| 时机 | 动作 |
| --- | --- |
| 用户开始计时 | 请求音频焦点 → 激活 MediaSession → 启动 `mediaPlayback` 前台服务（静音保活）→ 按键归本 App |
| 计时完成 / 用户结束 | 停止静音播放 → `setActive(false)` 释放会话 → 停止前台服务 → 按键归还音乐 App |
| 暂停超过阈值（默认 10 分钟，可配置） | 同上释放；用户继续时重新霸占 |
| 音乐 App 被用户主动唤起播放 | 本 App 收到焦点丢失回调 → 暂停计时并提示（设置项可改为「保持霸占、暂停音乐」） |

配套用户预期管理：设置项「听歌时按键归属」（默认仅计时开启时归计时）；首次霸占时一次性引导说明；常驻通知文案明示当前按键归属。

### 5.4 Android 14 前台服务策略

- 声明 `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 权限，`foregroundServiceType="mediaPlayback"`；
- `POST_NOTIFICATIONS` 运行时申请，拒绝时降级为「仅亮屏可用」并引导开启；
- audio_service 配置 `androidStopForegroundOnPause=false`，保证暂停计时期间 FGS 与通知常驻；
- 引导用户将 App 加入电池优化白名单（封闭 ROM 无激进杀后台，主要防 Doze 推迟唤醒）。

### 5.5 按键声震反馈设计（ADR-0005，V0.1 核心需求）

免触屏场景下，按键没有反馈等于盲操作——用户无法确认指令是否被接收。声震反馈因此与按键映射同等级，是体验的第一优先级：

- **确认音**：每次命令被接收即播放短促「滴答」确认音（本地音频资产，`just_audio` 低延迟模式播放）；开始/暂停/结束/跳过使用可区分的音型，盲操作时凭声音即可确认语义；
- **震动**：与确认音同步触发短震动（`vibration` 包），作为口袋/嘈杂环境下的兜底通道；
- **延迟要求**：从 KeyEvent 到达到反馈发出的端到端延迟 **<100ms**，纳入真机验收标准；
- **可分别开关**：提示音、振动、提醒音量在设置页分别开关（图书馆等安静场景，对应 US-G03）；
- **音频焦点联调**：确认音播放遵循 ADR-0001 的音频焦点策略，避免打断用户听歌（短促确认音使用 transient 焦点或不请求焦点，按真机联调确定）。

### 5.6 按键 KeyCode 自检工具（吸收自第三方报告的好点子）

- 设置页内嵌「按键自检」工具页：实时显示最近一次收到的物理按键 keyCode、解析出的语义事件（单按/长按/下一曲……）与最终分发的 Command；
- **首启自检**：首次启动引导用户依次按一遍侧边键，确认 85/87/88 出厂映射与 FN 键实际键码——**FN 键码不靠猜**（第三方报告直接猜测 `KEYCODE_FUNCTION`，未经实测，其代码示例可信度见评审 §2.3），以自检工具实测为准；
- **重新校准**：M500 系统 OTA 更新可能改变按键行为（风险 R8），用户可自助打开自检页确认并重新校准，映射表持久化可配置；
- 自检页同时兼任开发期的 KeyCode 探测工具，替代第三方报告中的临时 `onKeyDown` 日志方案。

## 6. 数据层设计（drift，见 ADR-0002）

表设计草案：

```sql
-- 专注时段：一次完整专注的记录单元
CREATE TABLE focus_session (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  start_epoch_ms INTEGER NOT NULL,
  end_epoch_ms INTEGER,
  planned_phases INTEGER NOT NULL,        -- 计划阶段数
  completed_phases INTEGER NOT NULL DEFAULT 0,
  total_focus_ms INTEGER NOT NULL DEFAULT 0,
  total_pause_ms INTEGER NOT NULL DEFAULT 0,
  tag TEXT,                               -- 任务/标签（US-B05）
  status TEXT NOT NULL,                   -- active/completed/aborted
  relapse_count INTEGER NOT NULL DEFAULT 0 -- 切出违约次数
);

-- 阶段事件流：状态机每次迁移一条
CREATE TABLE phase_event (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id INTEGER NOT NULL REFERENCES focus_session(id),
  phase_type TEXT NOT NULL,               -- focus/short_break/long_break
  event TEXT NOT NULL,                    -- start/pause/resume/extend/skip/end
  epoch_ms INTEGER NOT NULL,
  payload TEXT                            -- JSON，如 extend 的毫秒数
);

-- 每日应用使用统计（usage_stats 聚合落库）
CREATE TABLE usage_stat_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,                     -- YYYY-MM-DD
  package_name TEXT NOT NULL,
  total_ms INTEGER NOT NULL,
  launch_count INTEGER NOT NULL DEFAULT 0,
  UNIQUE(date, package_name)
);

-- 应用规则（白名单/拦截；拦截功能已移出路线图，表结构保留备查，ADR-0005）
CREATE TABLE app_rule (
  package_name TEXT PRIMARY KEY,
  rule TEXT NOT NULL,                     -- whitelist/block
  updated_epoch_ms INTEGER NOT NULL
);

-- 目标与习惯（已随功能砍除，表结构保留备查，ADR-0005）
CREATE TABLE goal (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL,                     -- daily_focus_ms / weekly_count / tag_daily
  target_value INTEGER NOT NULL,
  tag TEXT,
  created_epoch_ms INTEGER NOT NULL,
  archived INTEGER NOT NULL DEFAULT 0
);

-- 成就（同上，已砍，保留备查）
CREATE TABLE achievement (
  code TEXT PRIMARY KEY,
  unlocked_epoch_ms INTEGER,
  progress INTEGER NOT NULL DEFAULT 0
);
```

要点：统计页用 drift 流式查询（`watch()`）自动刷新；`phase_event` 事件流是统计与复盘的唯一事实来源；schema 迁移用 drift 自带 migration。**存储选型确认为 drift（结构化数据）+ shared_preferences（配置与按键映射表），不引入 Hive**——第三方报告的 Drift + Hive 双库方案对本产品是过度设计（ADR-0002，评审见 [04-批判评审](./04-批判评审与方案优化.md) §2.4）。

## 7. 数据收集设计（feature_usage，V0.3，见 ADR-0004）

- 依赖 `usage_stats` 包（[pub.dev/packages/usage_stats](https://pub.dev/packages/usage_stats)）封装 `UsageStatsManager`；
- **切出判定**：计时进行中以 1-3 秒间隔轮询 `queryEvents`，最新 `MOVE_TO_FOREGROUND` 事件的包名 ∉ {本 App, 白名单} → 记录一次切出违约（Relapse）并通知 focus 模块；
- **授权流程**：检测 `PACKAGE_USAGE_STATS` 授权状态 → 未授权则展示用途说明页 → 跳转系统「使用情况访问」设置页 → 回流后复检，未授权可跳过（功能降级，不阻塞计时）；
- 聚合任务每日闲时将原始事件聚合进 `usage_stat_daily`，原始事件定期清理；
- M500 为封闭定制 ROM，使用情况访问页路径由系统定制方确认，引导页截图/文案随 ROM 适配。

## 8. 厂商 ROM 适配策略

- **M500 定制 ROM（主目标）**：封闭系统、无第三方激进杀后台机制；适配清单收敛为：电池优化白名单引导、通知权限、使用情况访问引导、自启动开关确认（若 ROM 提供）、勿扰模式下的提醒音策略。
- **通用 Android（未来手机版预留）**：参照 dontkillmyapp 清单按厂商引导（小米自启动+无限制省电、华为手动管理、OPPO/vivo 后台冻结白名单、三星休眠应用例外），代码中按 `Build.MANUFACTURER` 路由到对应引导页——该能力在 Platform 层以插件形式预留，MVP 不启用。

## 9. 扩展性设计

1. **Command 模式按键重映射**：按键 → Command 的映射表存于 drift/设置，运行时可改（US-A08，V0.2）；新增按键（FN）或新手势（双击/三击启用）只需扩展解析器与映射表，不动引擎——FN 键一键开始上次模式（V0.2）走此路径；音量旋钮已决定不占用，保持系统音量职能（ADR-0005）。
2. **Feature 插件化目录**：每个 feature 自含 UI / Provider / Repository 绑定，版本裁剪 = 增删目录 + 装配层一行注册（ADR-0003）。
3. **AnalyticsSink 抽象**：Core 层定义 `AnalyticsSink { void track(String event, Map<String,Object?> props) }`，MVP 实现为本地日志 sink，V1.0 可无缝切换为上报 sink；数据收集与上报解耦。
4. **主题/皮肤预留**：设计 token（字号、间距、色板）集中在 `app/theme.dart`，5 英寸小屏默认大字体大按钮；皮肤包仅需替换 token 表。
5. **计时模式扩展点（一模式一引擎）**：产品边界只开放番茄倒计时 + 正计时两种模式（ADR-0005），但工程上为新模式预留明确接缝——每种计时模式是一个独立的纯 Dart 引擎类（`timer_engine.dart` = 倒计时，`count_up_timer.dart` = 正计时），互不 import、互不修改；新增模式（如 50/10 预设之外的独立模式、Flowtime）= 新建同类引擎文件 + FocusController 装配处按用户所选模式注入，已有引擎与测试零改动。

## 10. 风险登记册

| # | 风险 | 等级 | 说明与缓解 |
