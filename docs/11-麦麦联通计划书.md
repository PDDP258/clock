## 0. 结论速览（v3）

1. **定位**：把麦麦当作 `LlmProvider` 的**又一个后端**，现有四个触点（周报解读/当日点评/周报问答/当日问答）交互一行不改。**不做对话框**（`docs/08 §7` 明令，M500 打字困难）。
2. **通道修正（v3 关键）**：麦麦 WebUI 的 `agent` 域**不是麦麦**——它是 **ACP 外接程序**（`src/webui/routers/agent.py` → `src/agent/service.py`，`backend="acp"`），连的是外部 CLI agent **dsh**（自己的模型与凭据），**不经过麦麦人格/planner/插件工具**，且 `bot_config.toml` 第 4~5 行 `[agent] enabled=false`（**当前关闭**）。
   **真通道 = 网页聊天室（internal chat）**：`platform="internal"`、`user_id="owner"`、`bot_id="self"`（`src/core/internal_chat.py`）→ `chat_bot.message_process()` 走**完整麦麦链路**（`chat/service.py:1285`）；官方定为一等公民（`heartflow_manager.py:154`）。入口二选一：
   - App 直连 WS `/api/webui/ws`（需 cookie + 60s 一次性 ws-token）
   - **插件侧 `internal_chat.send(text)`（推荐）**：`plugin_runtime/capabilities/internal_chat.py`，**无需任何凭据**（在麦麦进程内）
3. **走"桥"而不是直连后台**：App 只跟一个**麦麦插件起的本地端口**说话（nginx 反代 `/ai/*` 并**免 basic**）；App 只持 **App 专用 token**，**麦麦后台的 `access_token` / basic 口令永不进 App**（否则等于把 418 个后台 API 的权限装进手机）。
4. **记忆联通（v3 新增约束）**：`internal` 会话**天然不写、也不读**记忆（PD 实测：A_memorix 零记录 / 文本级 5/5 未命中 / 双向 False）。⇒ **"联通"不会因接上 internal 通道而自动发生**，必须由桥**显式**搬运：
   - 方向 A（麦麦 → AI_clock）：桥**读**麦麦记忆 → 写进 `mikufocus_ai_memory.jsonl` 的 `memory` 键（应用永不覆盖）→ 自动注入。
   - 方向 B（AI_clock → 麦麦）：桥把近 7 日 `facts`/`note` 送进麦麦**长期记忆**——⚠️ **不能靠 `internal_chat.send()`**（它不写记忆），需走记忆写入通道（见 §6）。
5. **本项目早有预留**：`docs/08 §C2`（自定义 OpenAI 兼容端点）、`§C3`（配置导入）、`docs/07 §9 R11`（内置代理需限流+用量封顶）。桥若暴露 **OpenAI 兼容**接口，AI_clock 侧**只需 C2 + C3**。
6. **需立 ADR-0007**（ADR-0006 §6 边界条件）。


## 3. 方案

```
(A) 生成后端
    App 现有四触点 → LlmProvider → 指向「桥」暴露的 OpenAI 兼容端点（走 §C2，App 侧零新代码）
                                 或 新增 MaibotLlmProvider（若桥只暴露自有协议）

(B) 麦麦记忆 → MikuFocus（联通·方向 A）
    桥读麦麦记忆 → App 拉到 → 写本地 JSONL 的 memory 键 → 自动注入

(C) MikuFocus → 麦麦（联通·方向 B）
    App 送近 7 日 facts/note → 桥 → 写进麦麦长期记忆
    ⚠️ 不能用 internal_chat.send() 送达（它不写记忆）；须走记忆写入通道（§6）
```

### (A) 生成后端（App 侧最小）
- **首选**：桥暴露 **OpenAI 兼容** `/v1/chat/completions` ⇒ 做 `docs/08 §C2` 即可，**App 侧零新 provider**。
- **备选**：桥只暴露自有 HTTP 协议 ⇒ 新增 `lib/core/ai/maibot_provider.dart`（`MaibotLlmProvider implements LlmProvider`，复用 `LlmTransport` 接缝做单测）。
- 两者都**不引入基本认证/cookie/自签证书到 App**（除非走 8080 自签；见 §7）——桥走 nginx 时用 **Bearer(app 专用 token)**。

### (B) 麦麦记忆 → MikuFocus
- 新增 `lib/features/ai/application/maibot_memory_sync.dart`：拉「记忆摘要」→ `AiMemoryLog.upsert` 写当日 `memory` 键 → 下次请求自动注入。
- 写作规范：`memory` ≤200 字（注入截 60 字）；**不得**写入涉私内容（会随请求外发给 AI 服务商，`docs/09 §9`）。

### (C) MikuFocus → 麦麦
- 送近 7 日 `facts`/`note`（白名单聚合字段）→ 使其在 QQ 侧能聊专注数据。
- **v3 约束**：`internal_chat.send()` 只是"对麦麦说一句话"，**不会进长期记忆**（实测）⇒ 要"记得"，必须走记忆写入（§6）。
- 兼作 `docs/08 §C1`（建议兑现追踪）的数据底座。

## 5. 数据契约

### 5.1 App → 桥（推荐形态）
```http
POST https://203.195.219.170/ai/chat        # nginx：该路径免 basic
Authorization: Bearer <app 专用 token>
Content-Type: application/json
{ "text": "<system 约束>\n\n<user 提示词>", "client_msg_id": "<uuid>" }

→ 200 { "reply": "...", "ts": ... }
→ 401 → 提示重配（不自动重登）   → 5xx/超时 → 退避重试 ≤2 次
```
桥内：`internal_chat.send(text)` → 取回复 → 转 JSON。

### 5.2 记忆联通（现成 JSONL，不改格式）
```json
{"schema":"aiclock.ai_memory/1","date":"2026-10-31","rev":4,
 "updated_at":"2026-10-31T22:10:00+08:00",
 "facts":{"focus_minutes":95,"sessions":3,"rounds":4,"longest_segment_minutes":50,
          "interruption_count":2,"interruption_minutes":5,"best_slot":"下午"},
 "note":"今天 95 分钟里有 50 分钟是连着的一段。",
 "memory":"昨天在赶论文，夜里效率反而高。",
 "source":"maibot-bridge"}
```
- `memory` 由 App 的同步服务写入；想加来源/标签用**非注入外部键**（只保留、不注入）。

## 6. 麦麦侧：桥与"联通"的实现

**桥**（必须做成麦麦插件，才能调 `internal_chat.send()`；**插件不能注册 WebUI 路由** ⇒ 自起 aiohttp 端口 + nginx 反代）：

| 方向 | 做法 | 注意 |
|---|---|---|
| App→麦麦（对话） | 桥收 `/ai/chat` → `internal_chat.send(text)` → 回 JSON | 走麦麦完整链路（人格/planner/工具） |
| 麦麦→App（记忆） | 桥**读**麦麦记忆（`GET /api/webui/memory/*` 或直接读 A_memorix）→ 存成"给 AI_clock 的记忆片段"供 App 拉 | **不要**假设 internal 会话自带记忆 |
| AI_clock→麦麦（数据） | 桥把 `facts/note` 写入麦麦长期记忆（`memory/profiles/override` 或记忆导入链路；**非** `internal_chat.send()`） | 需 PD 确认用哪条写入通道 |

**备选中转**：WebDAV（`https://203.195.219.170/dav/`）——AI_clock 把记忆文件 PUT 上去、桥读；桥把要注入的记忆写成文件、App 拉。**复用已验证通路**，不改麦麦内核。

## 7. 边界与坑

| 场景 | 处理 |
|---|---|
| **凭据最小化** | App **只存 App 专用 token**；`access_token`/basic 口令**留服务器**（否则=418 后台 API 全权限进手机） |
| nginx | 为 `/ai/*` **单开免 basic**；其余后台路径保持 basic |
| **不做对话框** | 严禁输入框；麦麦能力只经 chip/按钮呈现（`docs/08 §7`） |
| 计时进行中触发网络 | **禁止**；同步只在用户主动查看 AI 时（或沿用既有 `autoInterpretIfDue` 纪律） |
| 自签证书 | 仅当桥走自签 8080 时才需要 `badCertificateCallback`；走 443 则不用。**别全局放行** |
| R11 限流 | 麦麦=内置代理 ⇒ 必须**用量封顶**（建议同时做 `D3 usage 记账`）；服务器 2C2G，勿高频 |
| 双向环膨胀 | 同步服务**按日期幂等**；只回送 `facts/note`，**不回送 `memory`** |
| 记忆写入 | ⚠️ `internal_chat.send()` **不写记忆**（实测）；别指望它让麦麦"记住" |
| 麦麦侧改动风险 | 改 `plugins/` 前**必跑** `/opt/maibot-qr/check_busy.py`；插件改完 `touch plugin.py` 即可 |
| Key 输入摩擦 | 用 §C3 配置文件导入 |
| 隔离（对照日记侧） | internal 会话天然与 QQ 记忆隔离（实测）；AJ_clock 若要"联通"，是**主动搬运**，不是放开隔离 |

## B.2 F1 · 桥通道（前置）

**F1.1 桥服务**
- 目标：在麦麦进程内提供一个**只做"聊天"一件事**的 HTTP 端点，内部调 `internal_chat.send(text)`。
- 形态：麦麦**插件**（`plugins/diary-ai-bridge/`）→ `@MessageGateway`/`on_load` 中**自起 aiohttp**（`plugin_runtime` 无 WebUI 路由接口，只能自起端口）。
- 端口：绑 `127.0.0.1:<port>`（**不对外**，由 nginx 反代）。
- 触发：插件加载即起；卸载即停。
- 降级：端口占用/起失败 → 日志告警，`/ai/*` 返回 503。
- 测试：服务器上 `curl 127.0.0.1:<port>/ai/chat`；插件重载后端口仍在。
- 验收：**PD 指出的唯一剩余验证 —— 插件能否稳定跑起监听**（含麦麦重启后自恢复）。

**F1.2 nginx**
- 目标：对外只暴露 `/ai/*`，且**免 basic**、走 Bearer。
- 落点：443（diary 站点）或独立 server 块加 `location /ai/ { proxy_pass http://127.0.0.1:<port>; }`。
- 风险：**其余后台路径（418 API）必须仍受 basic 保护**。
- 验收：`curl -H "Authorization: Bearer ..." https://.../ai/chat` 通；无 token → 401；访问 `/api/webui/*` 仍 401。

**F1.3 App 侧服务**
- 目标：`maibot_ai_service.dart` 提供 `chat(text)`。
- 落点：`lib/services/maibot_ai_service.dart`（沿用现有服务层写法：static/类 + 工厂）。
- 触发：仅用户主动查看 AI 时（安静原则）。
- 降级：`LlmFailure` 五分类复用（`network/timeout/unauthorized/quota/badResponse`）。
- 测试：`LlmTransport` 式接缝（注入假 HTTP）→ 覆盖 200/401/超时/坏 JSON。
- 验收：真机发一条 → 收到回复；断网 → 静默降级。

**F1.4 设置页**
- 目标：填 `base_url` + `app_token`，一键测试连接。
- 落点：`settings_page.dart` AI 区（`_AiSection`）。
- 拒绝项：**不得**出现 basic 用户名/口令、`access_token` 输入框。

## B.4 F3 · 记忆联通（双向）

**F3.1 方向 A（麦麦 → AI_clock）**
- `maibot_memory_sync.dart`：`pull()` → `GET /ai/memory` → `AiMemoryLog.upsert(当日, memory: ...)`。
- 触发：用户打开 AI 结果后 / 每日首轮完成（沿用既有挂点，不新增打扰）。
- 幂等：`maibot_memory_sync_at` 同日只拉一次；`memory` 写入前比对，相同不写。
- 降级：拉取失败 → 保留旧 `memory`，不报错。
- 验收：注入生效（解读内容体现记忆）；**离线时零请求**。

**F3.2 方向 B（AI_clock → 麦麦）**
- `push()` → `POST /ai/focus`，body = 近 7 日 `facts`+`note`（**白名单聚合字段，无钟点/应用名**）。
- 幂等键 = 日期（服务端 upsert）。
- **不送 `memory`**（防双向环膨胀）。
- 验收：麦麦侧可查询到专注数据；重复推送不产生重复记录。

**F3.3 防环**
- 规则：**A 拉 B 推分离**；`memory` 只由 A 写、`facts/note` 只由 B 推；两者不回流。
- 拒绝项：不得把 `internal_chat.send()` 当记忆写入通道。

## B.5 F4 · 新触点（嵌入）

**F4.1 标签建议**
- 数据：`CurrentTagNotifier` 的标签清单（≤12）+ 最近会话 `facts`。
- 契约：`{"schemaVersion":1,"options":[{"text":"论文","reason":"…"}],"notes":""}`。
- 交互：**建议 + 用户点选确认**（chip 形式，不做输入框）；**AI 永不直接写业务表**（落既有红线）。
- 落点：会话结束卡/详细页；数据源 `DailySummary`。
- 降级：失败静默不显示。
- 验收：给出 ≤3 个候选、点选后写标签、可拒绝。

**F4.2 建议兑现追踪（`docs/08 §C1`，零 LLM）**

- 本地三值判定：如「集中上午」→ 比本周时段占比（已见效/未见效/无法判定）。
- **零新增 LLM 调用、零新增上传字段**。
- 验收：回看上周建议 + 判定文案；无网络请求。

**F4.3 记忆摘要导出**

- 落点：设置页「跨程序记忆日志」旁加「导出摘要」。
- 验收：导出文件含近 N 天、无钟点/应用名。
